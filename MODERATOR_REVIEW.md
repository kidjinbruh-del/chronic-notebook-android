# Комментарий для модератора

Приложение «Дневник давления» — личный дневник самоконтроля артериального давления.
Ниже пояснения, которые обычно нужны при проверке. Текст можно отправить как есть.

---

**Что это и что это не является**

Приложение не является медицинским изделием. Оно не проводит диагностику, не
назначает лечение, не меняет дозировки и не содержит базы лекарственных
взаимодействий. Пользователь вносит только те препараты, которые уже назначены
врачом, и только те цифры, которые сам измерил тонометром. Внутри есть
экспертная оценка уровня давления по общепринятым порогам и предупреждение
вызвать скорую при 180/120 и выше — это текстовая подсказка, а не медицинское
решение.

**Данные и сеть**

Все записи хранятся только на устройстве в локальной базе SQLite через Room.
Аккаунтов, серверов, аналитики, рекламы и сторонних SDK нет — в приложении
используются только AndroidX и OkHttp. Интернет запрашивается в одном случае:
чтобы получить историю погоды и посчитать корреляцию «погода → давление».
Запросы идут на open-meteo.com и Яндекс.Погоду и не содержат медицинских
данных: передаются только координаты и дата. Без сети приложение полностью
работает, кроме блока корреляций.

**Разрешения**

- `POST_NOTIFICATIONS` (Android 13+) — уведомление о том, что наступило время
  приёма назначенного препарата.
- `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` — чтобы напоминание о приёме
  пришло в заданное пользователем время, а не в произвольный интервал.
- `RECEIVE_BOOT_COMPLETED` — после перезагрузки телефона восстановить будильники,
  которые Android сбрасывает.
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` — открыть системный экран с просьбой
  отключить оптимизацию. Это делается вручную пользователем и нужно, чтобы
  энергосбережение на агрессивно настроенных прошивках не сдвигало время
  приёма. Приложение само эту настройку не меняет.
- `INTERNET`, `ACCESS_NETWORK_STATE` — только погодные запросы.

**Замечание о точных будильниках**

Приложение объявляет и `SCHEDULE_EXACT_ALARM`, и `USE_EXACT_ALARM`. Второе
разрешение выдаётся только для приложений, чья основная функция — будильники
или расписание, и не требует отдельного разрешения пользователя. Здесь это
спорный случай: по смыслу напоминание о приёме лекарства — это будильник,
но формально приложение ведёт себя как дневник. Если условия политики не
выполняются, `USE_EXACT_ALARM` следует убрать и оставить только
`SCHEDULE_EXACT_ALARM` с явным разрешением: поведение при этом не меняется,
потому что основной путь — `setAlarmClock`, а точный запуск используется как
запасной.

`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` используется по назначению: кнопка
«Отключить экономию» открывает системный запрос снятия оптимизации для
этого пакета, а не меняет настройку молча. Настройку всё равно подтверждает
сам пользователь. Если сочтётся лишним, экран можно заменить на общий список
приложений — на работу напоминаний это не влияет, основной механизм
`setAlarmClock` от оптимизации батареи не зависит.

**Что стоит проверить при модерации**

1. Добавление препарата: название, доза, единица, «с едой», кто назначил, любое
   время приёма через выбор часа и минут. Слотов может быть сколько угодно.
2. Редактирование препарата: на карточке кнопка «Редактировать», после
   сохранения уведомления пересчитываются.
3. Эскалация: если не отметить приём, напоминание повторяется через 15, 45 и
   120 минут, затем кнопка «Принял» в уведомлении.
4. «Ожидают отметки» на вкладке «Лекарства» показывает приёмы на ближайший
   час, включая ещё не наступившие. Кнопка «через 15 мин» отсчитывается от
   времени приёма и не может перенести напоминание раньше назначенного.
5. Отчёт врачу: текст с базой, средними, корреляциями и факторами риска.
   Считается по всей базе, а не по видимой части списка.
6. Экран «Диагностика» внизу вкладки «Дом»: версия, состояние точных
   будильников, оптимизация батареи, последняя ошибка приложения.
7. После сохранения замера счётчик «Личная база» на вкладке «Дом» должен
   сразу показывать новый счёт.

**Совместимость и подпись**

minSdk 23 (Android 6.0 и выше), targetSdk 35. APK содержит все четыре
архитектуры: arm64-v8a, armeabi-v7a, x86, x86_64. Подпись — только официальный
ключ разработчика, схемы v1, v2 и v3 одновременно, что нужно старым прошивкам.
Отладочная сборка имеет отдельный applicationId с суффиксом `.debug`, в
продакшен не попадает.
